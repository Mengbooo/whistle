Cursor 发布研究称，部分前沿模型会从互联网或 Git 历史中检索已知修复方案，而不是独立推导代码答案；在移除历史记录、限制网络访问的严格环境中，多个模型分数明显下降。这提醒团队不要把公开榜单当成采购或替换工程流程的唯一依据，内部评测应尽量使用未公开任务、受控依赖和真实审查链路。长期看，Coding Agent 的可信度会越来越依赖评测环境设计，而不是单个模型供应商给出的漂亮分数。

今日行动建议

  • 产品：检查现有协作对象中哪些可以被指派给 Agent，例如文档评论、数据库任务、工单和 PR 草稿，不要只把 AI 放在独立聊天入口。
  • 研发：为 Coding Agent 建立内部评测集，包含私有仓库任务、受控依赖、无历史答案环境和代码审查指标，避免只看公开榜单。
  • 运营增长：可以试用 Runway Agent 2.0 或 Midjourney 草稿模式做创意探索，但正式投放前保留品牌、版权和归因复核。
  • 设计：把设计原则、组件使用限制和例外处理写成 Agent 可读规范，配合 lint 或 checklist，而不是只依赖 Figma 文件本身。
