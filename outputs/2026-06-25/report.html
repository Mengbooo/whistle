今日头条

Gemini 3.5 Flash 将计算机使用能力内置进主模型

Google 把 Computer Use 从独立能力整合进 Gemini 3.5 Flash，开发者可通过 Gemini API 和企业 Agent 平台构建跨浏览器、移动端与桌面的智能体，并获得敏感操作确认、间接提示注入检测等企业保护。它的重要性在于，计算机使用正在从演示型能力变成主力模型的默认工具接口，适合软件测试、跨应用知识工作和内部流程自动化团队优先试验。长期看，Agent 的竞争会越来越少停留在“会不会点屏幕”，而更多取决于身份、权限、审计和失败回滚是否产品化。

AI Agent来源：Google Blog · HN 168 分

Qwen-AgentWorld 开源，用世界模型训练 Agent 先预测再行动

通义千问发布 Qwen-AgentWorld，覆盖 MCP、搜索、终端、SWE、Web、OS、Android 等场景，并基于超过 1000 万条真实交互轨迹训练，让 Agent 可以先模拟环境结果再执行动作。它给研发团队的启发是，Agent 可靠性不只靠更强的通用模型，还要靠可复现环境、轨迹数据和任务级评测。对于需要构建企业 Agent 的团队，这类“环境模拟器 + 行动模型”的路线值得跟踪，因为它可能降低真实环境试错成本。

模型来源：通义实验室

豆包专业版上线，办公 Agent 开始以订阅套餐进入大众市场

豆包专业版基于豆包 2.1 系列，面向复杂办公与生产力场景，支持操作本地电脑、浏览器、调用 Skills、定时任务、Office 套件和生成带后端数据库的在线应用，标准套餐连续包月 68 元。这个信号比单纯模型升级更接近真实工作流：个人和小团队将用较低订阅成本测试“AI 办公执行者”，产品团队应关注用户会把哪些复杂任务外包给 Agent，也要留意本地操作、权限和数据边界如何被解释给普通用户。

产品来源：豆包

OpenAI 与 Broadcom 发布 LLM 推理定制芯片 Jalapeno

OpenAI 与 Broadcom 推出面向大语言模型推理优化的定制芯片 Jalapeno，HN 社区对相关报道讨论度很高。即使短期不会改变应用团队的日常开发，它仍是基础设施层面的强信号：头部 AI 公司正在把成本、吞吐和供应链控制向自有硬件延伸。对使用模型 API 的团队而言，值得关注的不是芯片名字，而是未来推理价格、延迟、上下文窗口和可用性是否因此出现新的平台分化。

基础设施来源：OpenAI · TechCrunch / HN

AI 与新工具

本板块保留较多条目，但只选会影响产品形态、开发流程或企业采用边界的信息。

ChatGPT 双向语音模型 Bidi 1 开始灰度测试

部分用户反馈 ChatGPT 网页版和 App 版出现 Bidi 1 语音模型，支持边说边听，用户可在模型输出中途打断并改写指令。语音输入天然更接近日常沟通，但更理想的 AI 输出会继续向视觉化、结构化、可交互演进，从原始文本到 Markdown、HTML，再到可操作界面或模拟环境。语音产品团队可以重点观察打断、轮次管理和多模态输出承接，而不是只比较音色自然度。

语音来源：IT之家

GPT-5.5 Instant 更新，强调意图理解和复杂约束执行

OpenAI 表示新版 GPT-5.5 Instant 更能理解问题背后的意图，并能更稳定地处理购物、本地推荐等带有复杂约束的任务。它不是一次高规格技术发布，但对消费级 AI 产品有现实意义：用户越来越少接受“泛泛回答”，更期待模型在价格、地点、偏好、限制条件之间做连贯权衡。做推荐、搜索和客服的团队可以把复杂约束样例纳入回归测试。

模型体验来源：OpenAI

Notion 用 Cursor SDK 将编码智能体嵌入文档与数据库

Notion 通过 Cursor SDK 在数周内把编码智能体接入产品，用户可在文档、讨论串或数据库任务里指派 Cursor 完成规划、构建、测试、验证并创建 PR。这里的关键不是 Notion 也能写代码，而是生产力工具开始把外部专业 Agent 变成可指派的工作对象。对 SaaS 产品来说，未来插件生态可能从“调用工具”升级为“委派角色”，而是否能保留上下文、权限和结果审计会决定体验上限。

开发工具来源：Cursor Blog

Figma 在 Config 2026 扩展画布能力，同时依赖第三方模型

Figma 将设计画布扩展到代码、动画、3D 深度、Shader 和可生成插件，并把团队提示词、技能和工作流复用纳入协作体系，但其 AI 能力仍依赖 Anthropic、OpenAI、Google 等外部模型。设计工具的长期问题正在变成“画布、代码和模型成本如何共存”：Figma 的优势是团队协作和设计资产，但如果模型供应商直接生成界面，它就必须把人类判断、工作流沉淀和组织记忆做得更强。

设计工具来源：The Decoder

Mistral Connectors 增加管理员控制、作用域密钥和调试器

Mistral 为 Connectors 推出工作空间级访问控制、连接器作用域 API Key、多账户连接、MCP 调试器，以及在 Vibe Code 和 Workflows 中复用连接器的能力。这类更新偏工程化，但对企业采用 AI 很关键：连接器越多，越需要把身份冒充、权限蔓延和长任务中断当作产品问题处理。接入 MCP 或内部工具的团队应尽早建立连接器权限矩阵，而不是等事故后补文档。

企业 AI来源：Mistral AI

Perplexity 推出面向法律工作的 Computer for Counsel

Perplexity 的 Computer for Counsel 将研究数据库、文档工具和案件管理系统连接起来，可从法律服务、签署和文档系统提取可引用来源，面向 Pro 与 Max 用户开放。它说明垂直行业 Agent 的卖点不只是“懂法律”，而是接通行业数据库、文档流和证据链。法律、财税、医疗等高责任场景的产品团队需要优先验证引用可追溯性和人工确认流程。

垂直 Agent来源：Perplexity

OpenRouter 推出统一图像 API，继续做多模型路由层

OpenRouter 发布统一图像 API，整合 Google、OpenAI、Black Forest Labs、Recraft、ByteDance、Microsoft、xAI 等 30 多个模型，并提供模型能力、端点定价、参数支持和流式预览。对应用开发者来说，它降低了多图像模型接入成本，但也把模型选择、成本控制和质量评估变成路由层能力。多模态应用如果不想被单一供应商绑定，可以关注这类抽象层，但要自建核心评测集。

多模态来源：OpenRouter

FFASR 发布真实远场 ASR 评测，补上语音模型落地短板

Treble Technologies 与 Hugging Face 推出 FFASR 排行榜，用真实远场声学条件评估 ASR，在混响、背景噪声、麦克风距离和不同信噪比下报告词错误率与实时因子。会议纪要、智能硬件、车载、监控和现场服务并不总发生在近场安静环境，传统基准容易高估能力。语音产品选型时应补充远场、多人、噪声和延迟测试，否则上线后的体验波动会被误判为用户问题。

评测来源：Hugging Face

大厂与平台动态

火山引擎发布 Agent Ready 基础设施和企业版 ArkClaw

火山引擎在 FORCE 大会上推出 Agent Ready 基础设施，AgentKit 覆盖 Identity、Runtime、Sandbox、Evaluation 等模块，ArkClaw 企业版接入 Agent 广场、技能中心、企业知识库和 IDP/SSO/OAuth 管控。它反映云厂商开始把 Agent 从模型能力包装为“身份、运行时、沙箱、评估、入口”的整套基础设施。企业内部如果要规模化上线 Agent，应把这些模块视作基本建设，而不是把单个对话框当成项目终点。

云平台来源：火山引擎

OpenRouter 称零数据留存模型流量已接近一半

OpenRouter 表示自 1 月以来新增 97 款支持零数据留存的模型，月度 token 量增长 4.3 倍，约占全部路由流量一半，并支持账户级、护栏级和单次请求级控制。这个数字提示企业 AI 采购正在从“模型效果优先”转向“效果与数据边界同时满足”。如果团队处理客户数据、代码或内部文档，ZDR 不应只是销售话术，而应被写入模型路由策略和日志策略。

数据边界来源：OpenRouter

Bunny DNS 宣布免费，开发者基础服务继续价格下探

Bunny 宣布将 DNS 服务免费化，在 HN 获得当日最高讨论热度。它不是 AI 新闻，但对独立开发者和中小团队有直接影响：基础设施供应商正在用低价甚至免费能力扩大入口，再通过 CDN、边缘计算、存储等服务承接商业化。工程团队可以评估 DNS 托管、监控、故障切换和供应商锁定成本，不必因为免费就忽略迁移与稳定性测试。

产品与增长观察

Interactive Brokers 接入 Grok，投资产品从洞察走向交易指令

盈透证券与 Grok 集成，用户可用自然语言做组合收益分析、风险情景建模、市场研究，并生成对冲订单等实时交易指令。金融 AI 的产品重点正在从“解释市场”推进到“连接账户与执行”，这会提高用户效率，也放大错误指令、适当性和责任边界问题。做交易、投顾或企业数据产品的团队应把确认、模拟、审计和撤销机制作为核心交互，而不是附属提醒。

金融产品来源：xAI

工程岗位数据显示，AI 自动化并未直接削弱工程招聘韧性

SignalFire 基于大规模公司和员工数据称，工程是 2025 年最具韧性的岗位：大型科技公司整体招聘较 2019 年下降 25%，工程岗仅降 11%，早期初创公司的工程招聘还高于 2019 年。这个信号不应被解读为工程师完全无风险，而是说明 AI 正在改变产出方式和岗位结构，尚未简单替代工程职能。团队更该衡量人均交付、代码质量、需求吞吐和维护成本，而不是只讨论“会不会失业”。

开发者与工程实践

字节披露 AI Coding 实践：代码生成率不是唯一指标

字节跳动技术副总裁洪定坤分享称，过去一年字节 AI 代码贡献率增长 6 倍、Token 消耗增长 5 倍，但 TRAE 团队代码超过 90% 由 AI 生成时，人均需求吞吐率只提升 60%；模型代码正确率可超过 80%，可交付性仍可能只有 40 到 60 分。这个复盘的价值在于把“AI 写了多少代码”拉回到交付质量、Harness 基建和协作治理。研发管理者应建立从生成到验证、测试、评审、回滚的完整指标。

AI Coding来源：火山引擎

NVIDIA NeMo AutoModel 用一行 import 提升 MoE 微调效率

NVIDIA NeMo AutoModel 基于 Transformers v5，加入专家并行、DeepEP 调度和 TransformerEngine 内核，在 MoE 微调中吞吐提升 3.4 到 3.7 倍，GPU 内存减少 29% 到 32%。对训练和微调团队来说，这类工具的实际意义是把原本需要分布式专家经验的优化封装进常用栈，降低大模型后训练门槛。采用前仍需用自己的模型规模、数据长度和硬件拓扑复测，不宜只看单个基准。

训练效率来源：Hugging Face

AI 生成 PR 噪音引发维护者治理讨论

HN 高分讨论将今天的 PR spam 类比为早期邮件垃圾信息，GitHub 近期也有关于限制 Pull Request 噪音的维护者文章。随着 AI Coding 工具降低提交成本，开源项目和企业内部仓库都会面临低质量 PR、重复修复和自动化贡献的治理问题。维护者可以提前设置贡献门槛、自动化检查、提交频率限制和 issue 绑定规则，把“能生成代码”与“值得进入评审队列”分开处理。

政策监管与合规

GitHub 与开源联盟呼吁修改加州 AI 透明度法案

GitHub 联合 Black Forest Labs、Hugging Face、Mozilla 等呼吁修改加州 AI 透明度法案相关条款，认为要求开发者在下游用户未履约时撤销开源许可证，与开源许可证永久不可撤销的性质冲突。这个议题对开源 AI 项目影响直接：监管若把责任链条简单压到上游，会改变模型、数据集和工具库的发布意愿。开源项目维护者应关注透明度文档、使用限制说明和下游通知机制，避免合规要求与许可证设计相冲突。

AI 招聘工具偏见研究提示 HR 自动化需要独立审计

斯坦福 HAI 报道的大规模实地研究显示，AI 招聘筛选工具可能导致黑人和亚裔申请者遭遇系统性排斥，且多个雇主依赖同一第三方算法形成“算法单一文化”。这不是泛伦理讨论，而是会影响企业招聘合规和雇主品牌的现实风险。采用 AI 简历筛选或面试评估的团队，应要求供应商提供群体公平性测试、可解释记录和人工复核流程，并定期用本企业数据做偏差审计。

今日行动建议

产品

把 Agent 功能拆成“可委派任务、权限确认、结果审计、失败恢复”四层来设计，不要只在现有页面上加一个聊天入口。

研发

为 AI Coding 建立可交付性指标：测试通过率、评审返工率、线上缺陷、维护成本和需求吞吐，比代码生成占比更有管理价值。

运营与增长

关注豆包专业版、Perplexity 法律 Agent、Grok 投资账户这类垂直工作流产品，测试用户愿意为哪些“执行型 AI”付费。

管理者与创业者

在模型选型之外同步评估 ZDR、连接器权限、开源许可证、算法审计和云供应商稳定性，把合规与基础设施成本提前计入路线图。
