开源模型

MiniMax M3 发布开源权重，代码、Agent、1M 上下文和多模态打包推进

MiniMax 发布 M3 开源权重模型，披露 428B 总参数、23B 激活参数，并给出 SWE-Bench Pro、Terminal Bench、KernelBench 等编码与 Agent 指标，同时采用稀疏注意力扩展至 1M token。它的价值不只在单项分数，而在把长上下文、代码执行、多模态和 API 工具一起交给开发者测试；未来代码模型竞争会更像“工程环境能力”竞争，而不是只比较聊天质量。

来源：MiniMax。
代码模型

Kimi-K2.7-Code 开源，推理 token 降低 30%

Kimi 发布并开源 Kimi-K2.7-Code，称相较 K2.6 在多个代码基准上提升，并将推理 token 使用量降低 30%。对高频使用 AI 编码的团队，成本下降与长时任务成功率同样关键，因为 Agent 失败往往消耗在反复试错和上下文膨胀上；值得用真实仓库任务测试它在端到端修改、回归验证和指令保持上的表现。

来源：Kimi.ai。
Agent

豆包上线“任务模式”，消费级 AI 应用继续向全链路执行器演进

豆包大范围上线任务模式，覆盖定时执行、网页生成、PPT、数据可视化分析等能力，并将“思考模式”升级为“专家模式”，同时推出从 68 元到 500 元每月的专业版。这个改动说明通用 AI 应用正在从对话框走向可调度的工作流入口，产品团队应观察哪些任务会从“问答”迁移到“定时生成文件与页面”；AI 输出形态也会继续从纯文本走向 Markdown、HTML 和可交互结果。

来源：IT之家。

今日行动建议

产品：把“对话模式”和“任务模式”分开评估，优先找出能定时执行、生成文件或产出可交互页面的高频场景。

研发：用一个真实仓库测试 GLM-5.2、MiniMax M3、Kimi-K2.7-Code 等代码模型，记录长上下文、端到端成功率、回归验证和成本。

运营与增长：重新计算 AI 订阅用户的重度使用成本，避免把少数高强度用户误判为健康增长。

管理者：在引入 Agent 前先建立 skills、权限、审计和供应商切换规范，避免组织流程落后于工具采用速度。

合规：面向客户准备一页式模型供应链说明，覆盖模型来源、数据处理、降级方案、人工复核和异常响应。
