Salesforce 以 36 亿美元收购 Fin，企业客服 Agent 进入并购整合期

Salesforce 宣布以 36 亿美元收购 AI 客服平台 Fin，后者原为 Intercom 旗下产品，覆盖实时聊天、WhatsApp、短信、电话和 Slack 等多渠道问题解决。它的重要性不只在交易金额，而在于企业软件厂商开始把“可直接接管客户服务流程的 Agent”作为核心平台能力收编；对 SaaS、客服、售后和实施团队来说，接下来更值得验证的是 Agent 在复杂工单、权限、知识库更新和人工接管上的真实闭环能力，而不是单点问答效果。

来源：TechCrunch / Salesforce / HN TechCrunch Salesforce

来源：OpenAI openai.com

Meta 在 Facebook 上线 AI Mode，平台搜索继续向“合成答案”迁移

Meta 在 Facebook 推出 AI Mode，用 Meta AI 从公开帖子、群组和 Reels 中提取信息并合成回答，同时继续加入 AI 照片、视频拼贴和创作者工具。这对内容平台和运营团队的影响在于，搜索入口不再只分发链接或帖子，而会把平台内部内容重组为答案；未来内容生产可能更依赖结构化信息、可引用事实和平台可读的素材资产，运营需要同时优化“被人看见”和“被 AI 摘要正确引用”。

五角大楼转移 Anthropic 工作流，AI 供应商的合规边界变成采购变量

AI HOT 收录的消息称，五角大楼已将超过三分之二日常 AI 工作流从 Anthropic 转移，目标 9 月前完全切断，争议源于 Claude 是否可用于大规模监控和全自动武器等协议边界。这类事件的工作含义是，AI 供应商的安全原则、政府合作立场和客户行业限制会直接影响企业采购连续性；依赖外部模型的团队应准备多模型路由、供应商退出预案和敏感场景的内部审查记录。

苹果解释 AI 版 Siri 推迟：从“加工具”转向完整重构

苹果项目负责人称，团队曾在旧 Siri 上做出小幅改良和工具调用版本，但因达不到产品愿景而推倒重来，改为基于新大模型、独立应用和全平台多模态体验重构。这个案例提醒所有做 AI 助手的团队：把工具调用缝到旧交互里通常只能得到增量体验，真正的助手产品会牵涉上下文、隐私、跨设备状态和输出形态的整体设计；AI 输出也可能从原始文本继续走向 Markdown、HTML 乃至更视觉化、结构化、可交互的界面。

MiniMax 开源 M3 与 MSA，长上下文多模态开源模型继续提速

MiniMax 开源 428B 总参数、23B 激活参数的 M3 模型权重，并发布 MiniMax Sparse Attention 技术论文，强调从预训练阶段进行文本、图像等多模态交错混合训练，输出速度已从约 30 TPS 提升至约 80 TPS。对模型选型团队来说，这类开源高性能模型的价值在于可控部署和长上下文成本下降；如果已有私有知识库、代码库或多模态任务，可以把 M3 纳入离线评测，而不是只看榜单排名。

来源：MiniMax mp.weixin.qq.com

Kimi K2.7 Code 高速版上线，编码模型开始显性区分速度档

Kimi K2.7 Code 高速版与普通版为同一模型，输出速度约为 5 到 6 倍，常规编程场景约 180 token/s，短上下文可达 260 token/s，但 API 定价和计划内消耗也更高。这里的信号是，编码 Agent 的瓶颈越来越多来自等待时间和长程任务吞吐，而不只是单次正确率；研发团队可以把高速模型用于短周期迭代、测试修复和并行会话，把普通模型留给成本敏感的批处理任务。

来源：月之暗面 Kimi mp.weixin.qq.com

Grok Build 推出 Agent Dashboard，多编码会话进入“调度台”形态

xAI 为 Grok Build 推出 Agent Dashboard，用单屏管理多个编码会话，按等待输入、工作中、空闲分组，并可查看输出、回复会话、设置模型和权限模式。它的重点不是又一个聊天入口，而是把编码 Agent 从线性对话推进到多任务调度界面；未来开发者工具很可能像运维控制台一样管理多个长跑任务，人负责审批、纠偏和验收，Agent 负责并行执行。

来源：xAI x.ai

DFlash 与 SGLang Spec V2 发布，投机解码继续压低推理延迟

Z Lab、Modal 与 SGLang 团队发布 DFlash 投机解码模型和 SGLang 默认 Spec V2 引擎，通过块扩散和 KV 注入并行生成 draft token，目标是提升大模型推理吞吐。对基础设施团队来说，推理优化已经成为产品体验和毛利率的共同变量；如果业务中存在高并发代码补全、客服或搜索摘要，应该把投机解码、缓存、路由和降级策略放进同一套成本模型里评估。

来源：LMSYS lmsys.org

Flash-KMeans 开源，向量与聚类基础算子仍有数量级优化空间

UC Berkeley 与 UT Austin 团队开源 Flash-KMeans，通过重构 GPU 数据流实现精确 Lloyd's k-Means，在部分基准上相对 FAISS 和 cuML 有显著速度优势，并支持大规模 out-of-core 场景。它对 AI 应用的现实意义在于，向量索引、稀疏注意力路由、KV 缓存压缩等环节仍会受底层算子影响；做检索增强、推荐或模型服务的团队，不应只优化上层 prompt，也要定期回看数据结构和 GPU IO 路径。

来源：MarkTechPost marktechpost.com

olmo-eval 发布，模型开发评测从发布前验收走向日常循环

Hugging Face 博客介绍的 olmo-eval 是面向 LLM 持续开发的评估工作台，支持 agentic、多轮评测、容器化隔离运行，并报告标准误差和最小可检测效应。它体现出一个重要趋势：模型和 Agent 的质量管理正在从“跑一组排行榜”变为开发循环中的持续观测；团队如果要稳定使用多模型或自训练模型，应尽早沉淀私有任务集、失败样本和可比较的评测记录。

来源：Hugging Face / AllenAI huggingface.co

今日行动建议

产品

评估现有搜索、客服、内容生成入口是否需要从“问答框”升级为可追踪、可引用、可回滚的工作流界面。

研发

把多模型路由、本地模型、评测集和 Agent 权限审查列入近期技术债清单，优先处理供应商切换和敏感代码场景。

运营

针对 Meta AI Mode 这类合成答案入口，开始整理结构化 FAQ、可引用素材和平台内公开内容，减少被错误摘要的概率。

管理者

AI 转型不要只做组织迁移，需同步定义管理半径、验收指标、合规记录和成本上限，尤其关注订阅制与 token 成本倒挂。
