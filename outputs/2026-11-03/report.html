早上好，先看几件正在改变实际使用体验的事：OpenAI 为并行开发重做 Git 后端，Anthropic 把长对话改为只传新增消息，Kimi 则把游戏引擎和创作软件接进同一套开发方案。代码、对话和工程文件的处理方式都在变化，但传输加快并不等于模型调用变便宜，生成原型也不等于完成正式产品。与此同时，LifeVal 与 GDPx 从日常事务和专业任务给出了差异很大的测评结果，能力分数必须连同任务范围、计分方式和安全限制一起理解。商业层面，Anthropic 披露高速增长背后的亏损与算力承诺，沙特阿美完成 HUMAIN 入股；使用政策更新和 Brave 版权诉讼，则把模型访问转售与检索内容授权的边界摆到了台前。工具能完成的步骤在增加，承接这些步骤的基础设施、付费方式和权限边界也在同步调整。

OpenAI 自研 Git 后端 Pando 投产，中位推送延迟降低近 80% ↗

OpenAI 披露，Codex 带来的并行开发量使原有单体仓库系统出现推送、抓取变慢和合并失败，可靠性一度低于 90%；以 Rust 编写的 Pando 在 10 周内从启动走到投产，已承载该仓库全部开发，保持现有 Git 工作流。

解读公司称，中位推送延迟降低近 80%，每天交付近 1 PB 的 Git 数据，单小时曾超过 57 TB，合并可靠性也得到改善；核心设计由一位工程师负责，实现交由多个 agent 团队完成，部分客户端改进已回馈上游。大量 agent 同时读写代码，把版本控制的传输和合并能力变成了开发吞吐量的限制，后端扩容直接影响并行任务能否稳定完成。

Anthropic 公测 message threads，长对话只传新增消息，计费不变 ↗

Anthropic 在 Messages API 公测 message threads：请求携带新增消息和上一条消息 ID，由服务端缓存历史；官方称，多数 Claude Code 用户已默认启用，50 万至 100 万 token 请求的首个 token 等待时间中位数缩短约 35%，长对话单次请求大小中位数从约 800 KB 降至 1.8 KB。

OpenAI，经 juya-ai-daily

OpenAI 披露激活分类器部署，违规输出可被中途拦截并复审 ↗

OpenAI 表示，自 GPT-5.6 起使用激活分类器监测所有助手回复，目前已部署于其最强模型的内部和外部流量，作为文本分类器之外的一层安全措施。这类轻量探针读取模型内部神经活动，可在输出中途拦截疑似违规内容并交由推理模型最终判定；

解读公司称红队测试中总体比基于内容的分类器更能抵抗越狱，但它依赖标注数据，仅能检测已知且可测量的不良活动，每个新预训练基础模型都须重新训练。安全判断由生成后文本审核延伸到生成过程内部，也引入暂停与复审步骤；该机制没有覆盖所有未知风险的保证。
