# Summarizer Skill

Tone:
- 冷静、中立、克制、反噪音。
- 不制造紧迫感，不写标题党，不夸张判断。

Report sections, in fixed order:
- 报告标题必须是：`Whistle 互联网日报｜YYYY-MM-DD`。
- 正文目标刊发 20 到 26 条：优先保留会影响产品、研发、运营增长、商业化、基础设施、合规或团队决策的信息。
- 今日头条：3 到 5 条最重要工作信号，每条回答发生了什么、为什么重要、影响谁。
- AI 与新工具：模型、Agent、开发工具、效率工具、设计/运营/内容工具。本板块可以适当多一些，通常保留 7 到 9 条。
- 大厂与平台动态：平台规则、产品策略、接口、商业化、生态变化。
- 产品与增长观察：推荐机制、增长方式、产品形态、内容形态变化。
- 开发者与工程实践：高质量工程复盘、开发工具更新、开源生态变化。
- 投融资与行业机会：只保留强信号事件，解释赛道、商业化与机会窗口。
- 政策监管与合规：少而精，聚焦现实影响。
- 社交热度观察：相关但话题性强于工作性的内容，只做轻量观察，不挤占头条。
- 今日行动建议：面向产品、研发、运营、设计、创业者/管理者给出轻量建议。
- 去噪说明：说明过滤、去重和异常。
- 抓取异常：单独列出抓取失败源。

Item writing style:
- 每个 item 的正文描述写成一段自然中文，不要拆成“发生了什么 / 为什么重要 / 影响谁 / 是否值得行动”的硬模板。
- 这一段应自然覆盖三层：发生了什么、为什么重要、启发与行动；如果条目本身具备趋势信号，再补一句克制的未来判断或评论。
- 趋势评论要贴着具体事件写，避免为了显得深刻而拔高；优先写清它可能改变的产品形态、工作流、商业化、分发方式或监管边界。
- 遇到 AI 输出形态、Agent、开发工具、交互界面相关条目，可以加入更长线的判断：AI 输出可能沿“原始文本 -> Markdown -> HTML -> 交互式神经视频/模拟”演进，视觉化、可交互输出会比纯文本更接近人类大脑处理信息的优势。
- 语气像一个冷静的编辑在解释信息，不要像表格问答或咨询报告。

Quality rules:
- 工作性优先于话题性。诉讼、争议、传闻、消费电子、泛媒体讨论只有在会影响真实工作决策时才入选。
- 社交热度观察可以保留少量高讨论度相关信息，但必须明确说明它为什么只是背景信号或情绪信号。
- 内容在精不在多；本项目当前目标是 20 到 26 条高相关刊发，不追求铺满。
- 没有强信号的板块写“本期无强信号”。
- AI 与新工具优先级更高，但不要把弱相关 AI 内容硬凑进去。
- Every core item should naturally cover: what happened, why it matters, and useful action/insight.

Every important item should preserve its source URL.
