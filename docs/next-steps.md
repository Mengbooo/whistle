# Whistle 后续开发方向

本文记录 Whistle 下一阶段的主要改进方向：日报内容结构持续打磨、前端归档网站增强，以及邮件订阅与发布链路完善。

## 1. 日报内容结构升级

参考 [internet-news-daily-sections.md](./internet-news-daily-sections.md) 重新设计 Whistle 的信息源与日报板块。

### 目标

- 从“信息聚合”升级为“低噪音互联网工作日报”。
- 内容要降低噪音，但不是越少越好；优先保留真正影响互联网从业者工作判断的信息，并尽量保留主信息源中的关键事实。
- AI 与新工具板块可以适当扩大篇幅，因为这是当前最强相关主题。
- 每条核心内容用一段自然中文讲清楚：先保留来源事实，再解释为什么重要、启发与行动；遇到强趋势信号时，补一句克制的未来判断或编辑评论。
- 保留一块“社交热度观察”，专门承接相关但话题性强于工作性的高讨论信息，避免它挤占今日头条和核心工作信号。

### 信息源更新

后续需要围绕以下板块重新整理 `sources.yaml`：

- 大厂与平台动态：OpenAI、Google、Meta、Microsoft、Apple、Amazon、字节、腾讯、阿里、微信、小红书、B 站等。
- AI 与新工具：模型发布、Agent 工具、开发工具、设计工具、运营工具、内容生产工具。
- 产品与增长观察：产品改版、平台规则、推荐机制、增长打法、商业化变化。
- 投融资与行业机会：融资、并购、SaaS、出海、广告、电商、新业务。
- 政策监管与合规：AI 监管、数据合规、平台治理、广告政策、隐私与跨境。
- 开发者与工程实践：GitHub、HN、工程博客、云厂商、开源项目。

### 日报板块建议

首版可以收敛为以下结构：

1. 今日头条
   - 3 到 5 条最重要信息。
   - 每条用一段自然中文说明：先保留来源事实，再解释为什么重要、启发与行动；如果信息本身指向产品形态、工作流、商业化或监管变化，可以加入未来趋势评论。

2. AI 与新工具
   - 可适当多一些，是 Whistle 当前最重要的内容板块。
   - 覆盖模型、Agent、开发工具、效率工具、设计/运营/内容工具。
   - 重点说明：能做什么、适合谁、相比现有方案强在哪里。

3. 大厂与平台动态
   - 聚焦平台规则、产品策略、接口、商业化、生态变化。
   - 不做公告搬运，要解释对业务和岗位的影响。

4. 产品与增长观察
   - 关注推荐机制、增长方式、产品形态、内容形态变化。
   - 更偏产品、运营、增长岗位视角。

5. 开发者与工程实践
   - 保留高质量工程复盘、开发工具更新、开源生态变化。
   - 避免把纯社区热度误判为核心趋势。

6. 投融资与行业机会
   - 只保留强信号事件。
   - 解释赛道、商业化与机会窗口。

7. 政策监管与合规
   - 少而精，聚焦现实影响。
   - 避免纯政策摘录。

8. 社交热度观察
   - 少量保留高讨论度相关信息。
   - 明确说明它是背景信号、情绪信号还是传播信号。
   - 不让社交热度影响核心排序，避免“话题性优先于工作性”。

9. 今日行动建议
   - 按人群给出轻量建议：产品、研发、运营、设计、创业者/管理者。
   - 不做宏大预测，只给可观察、可尝试、可跟进的动作。

### 内容质量原则

- 每期不要堆满低相关条目，但也不能因为“低噪音”误删高质量来源新闻；删除应限于重复、弱相关、过期或纯噪音内容。
- 优先一手来源，其次高质量分析，再其次社区讨论。
- 对弱相关内容明确标注为“背景信号”或直接过滤。
- 标题和事实骨架尽量保留原始来源，正文用中文重写并加入编辑解读，不照搬 RSS 摘要，也不把新闻抽象成只有观点的短评。
- 排序结果只是输入，最终取舍由 Agent 结合日报板块完成。
- 趋势判断必须基于具体条目，不做空泛宏大预测；例如 AI 输出形态相关信息可以讨论从原始文本到 Markdown、HTML、交互式神经视频/模拟的演进。

## 2. 前端网站搭建

已用 Vite + React 完成一个可静态导出的 MVP，构建产物位于 `site/`，可部署到 Vercel。整体风格保持当前 Kami 设计语言。

### 页面范围

1. 主页
   - 介绍 Whistle 是什么。
   - 展示最新一期日报入口。
   - 展示最近几期归档。
   - 保持克制，不做营销式 landing page。

2. 订阅页
   - 说明日报发送频率、内容范围、适合人群。
   - 预留邮件订阅表单。
   - 后续可接 Resend Audience、Buttondown、ConvertKit 或自建接口。

3. 归档页
   - 按日期列出全部日报。
   - 支持后续增加标签、板块、关键词筛选。
   - 当前阶段先使用静态 HTML/JSON 生成即可。

4. 日报页
   - 展示单期日报 HTML。
   - 提供 PDF 下载入口。
   - 保留来源链接。
   - 移动端阅读体验要舒服。

### 视觉风格

延续 Kami：

- 背景：暖纸色 `#f5f4ed`。
- 强调色：ink-blue `#1B365D`。
- 字体：serif-led，中文优先使用 Kami 字体栈。
- 布局：编辑感、留白克制、信息层级清晰。
- 卡片：只用于日报条目、归档条目、订阅表单等真实容器。
- 不使用花哨渐变、营销大 hero、装饰性图形。

### 技术建议

当前实现：

- `src/`：Vite + React 静态站源码。
- `archive/index.html`、`subscribe/index.html`：多页面入口。
- `public/reports/YYYY-MM-DD.html`：归档后的日报 HTML。
- `public/assets/report-YYYY-MM-DD.pdf`：归档后的 PDF。
- `site/`：最终静态部署目录。
- `pnpm run publish`：生成 PDF、归档报告、构建静态站点。

后续如果需要更强交互，可继续增强：

- 搜索。
- 标签筛选。
- RSS feed。
- 邮件订阅 API。
- 每期报告元数据 JSON。

### 近期可执行任务

- 接入 Resend 订阅与邮件推送配置。
- 为每期日报生成公开摘要元数据，供归档页和首页读取。
- 为归档页增加搜索、标签或板块筛选。
- 增加 RSS feed，方便用户用阅读器订阅。
- 将部署域名、Vercel 项目和定时任务配置固化到 README。
